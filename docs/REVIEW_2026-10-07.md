A separate Claude (Opus 5.5) agent, run as a subagent of the session doing the hardening work, with a fresh context. It was
given the repository read-only at `48ab26a` and told to invalidate the strongest claim, not to agree with the author. It was
**not** shown the author session's findings (the custody defect R1–R3, `docs/CUSTODY_RESULTS.md`, was found in parallel
and committed afterwards). **Same vendor and model family as the author session: this is separation of context, not
independence of judgment.** No human reviewed it.

`7a1f08b` (the reviewer's PoC scripts, re-pointed at the current tree), container only.

## Fixes

- F2: `AnchoredFileLedger.contains()` re-reads the file under the same lock `append()` uses. `FileLedger` (single-writer by
  its own docstring) is unchanged: two `FileLedger` instances on one path remain unsupported.
- F2b: `EvidenceWorkflow.run()` refuses a non-string or empty `record_id`/`input_digest` before anything runs.
- F5: `FileReservations.release()` and `complete()/unknown()` run under one directory lock (`.mutate.lock`, OS advisory lock,
  released if the holder dies). `reserve()` is unchanged (its claim is `O_CREAT|O_EXCL`). Windows path not validated.
- F4: the consumer resolves `--state` with `realpath` before locking or writing.
- F3: `--signature`, `--allowed-signers`, `--identity` must be given together (exit 2 otherwise), as in `verify_package.py`.
- F6a: `loads_bounded` refuses a float literal that does not fit a finite double.
- F6b: `OverflowError` is COULD NOT LOOK (exit 2) in the verifier and the consumer; the consumer also gained the verifier's
  other malformed-input exceptions.

## Addendum (2026-10-07, after CI at `b7d072b`)

The F2 regression test failed on `windows-latest`. `AnchoredFileLedger` is POSIX-only, and `contains()` now takes its lock
like `append()` does. That changed Windows behaviour for the better. At `48ab26a`, with `fcntl` removed (as on Windows),
the workflow executed and the ledger then refused: `effects = ['effect']`, no ledger file, so an effect with no record.
Since this commit's fix, the refusal comes before `execute()`. Neither the review nor this session had looked at Windows. The
test now follows the anchored ledger's platform convention: it skips without `fcntl`, and a monkeypatched test pins the
refusal-before-effect order on every platform (`docs/EX1_RESULTS.md`, Addendum 1).
