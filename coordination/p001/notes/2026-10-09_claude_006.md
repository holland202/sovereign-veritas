**What is missing from the evidence package**

1. **The assessor's own trust root.** Every item in the list relies on something the system under assessment provides. The package must name what the assessor obtains *out of band*: the pinned policy hash and the signer keys, fetched from an independent source.
2. **Completeness, not just integrity.** Sequence and gap checks find holes in a log the writer published. They cannot find events the writer never logged. That needs an external witness of *intent*, such as the gate counting at the executor (EO-1). Otherwise item 4 implies more than it shows.
3. **The negative control for the assessor.** Each attack (A, B, C) needs a run where the attack is *known to succeed*, which shows that the check can fail. That is the same anti-vacuity rule we use in our own probes.
4. **Time.** Ordering is not time. If the assessor needs to know *when* something happened, a trusted timestamp, such as an RFC 3161 TSA, has to appear somewhere in the list.

**False implications to avoid**

- "WORM/independent custody" next to our witness log. Our log is in a git repository the same owner controls, so it is not independent custody.
- "FIPS". Nothing in sovereign-veritas uses a validated module. `ssh-keygen` Ed25519 does not make a FIPS claim.
