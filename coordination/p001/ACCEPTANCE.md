## Common prerequisites and evidence semantics

- Build tests using fresh temporary directories and *throwaway Ed25519 SSH signing keys*, with explicit allowed-signers identity and `sv-package` namespace. Never use Chad's actual private key in CI; no secrets are committed. Tests are offline and deterministic wherever possible.
- Pin the exact `main` starting revision, test commands, Python/OS environments, original contract vectors and conformance digest. Verify source/evidence rather than trusting a reported green badge. `SCOPE_FROZEN` does **not** imply `ACCEPTANCE_FROZEN`.
- Distinguish `ACCEPTED` (success and state advanced), `REFUSED` (checks failed, state unchanged), and `COULD_NOT_LOOK` (required check unreadable/unavailable, state unchanged). Current CLI convention is exit 0/1/2 respectively; keep it unless an explicit, owner-reviewed CLI change is documented.
- For state nonmutation assertions, compare **exact file bytes before and after**, or assert state file absence both times. Existing consumed list and anchor are both covered. Do not count failure merely because a script prints the right text.
- **Anti-vacuity:** At least one valid authorized, signed, freshly witnessed v1 package must be accepted and persist state, and both v0 and v1 must remain inspectable under their allowed, clearly identified modes. A checker that refuses everything fails acceptance.
- Signatures attest the signed bytes under an approved key, not that the Gate decision is true, fresh or authorized by an external human. A contract digest attests version binding under local trust, not scientific/world truth.

## A — W1: production consumer refuses unauthenticated acceptance

**A01 — Positive control.** Given a newly generated `sv.package/1` whose contract fields match the trusted local contract, whose detached signature validates under a throwaway key/allowed-signers identity, and whose witness log places this package latest, `consumer accept` returns 0, reports authenticated acceptance, and writes a state file with exactly one consumed package digest and the expected witness anchor. On a second invocation with the same state/package/witness, it refuses (exit 1), and state bytes are unchanged. This tests a real successful workflow and replay resistance.

**A02 — Missing signature/configuration (K1/K2).** Production `consumer accept` requires **all three** CLI options `--signature`, `--allowed-signers`, and `--identity`. Test omission of each one separately, including the exact `--signature FILE` without `--allowed-signers` case that previously raised uncaught `TypeError`. Every incomplete invocation must end with **argparse usage exit 2**, `usage:` on stderr, no Python traceback, and *byte-identical* existing state (or continued absence). The usage error must not be described as a semantic `REFUSED` decision. Separately, complete but unreadable signature/trust material must produce a clearly classified `COULD_NOT_LOOK`/exit 2, not succeed.

**A03 — Invalid signature cases.** An altered package byte after signing, altered signature, wrong signer identity, unknown public key, and wrong SSH signature namespace must be refused (or `COULD_NOT_LOOK` when verification cannot be performed), with zero persistent consumer-state changes. The positive control with the correct key must still pass. No test may count “always fail signature verification” as a valid defense.

**A04 — Missing verification tool.** Simulate an environment with the required signature-verification executable unavailable *without modifying the real machine*. Exit 2 (or equivalently documented `COULD_NOT_LOOK`), never accepted and state unmodified. The harness must not confuse a bad test PATH setup with a valid negative result.

**A05 — Signature does not override other checks.** A correctly signed v1 package that is not the latest witnessed entry, a witnessed package that is repeated, a package with a broken semantic check, and a rollback/truncated previously anchored witness log all remain refused with identical persisted state. Conversely, a legitimate, distinct, latest-witnessed signed package that extends the existing witness log is allowed and advances state. Signing cannot bypass Gate, witness or anti-replay checks.

**A06 — No unsigned state-changing escape hatch (K7).** `consumer.py --allow-unsigned` must fail **argparse usage validation, exit 2**, leaving state byte-identical; no env-var bypass. The existing `tools/verify_package.py` is the **inspection path**; it must accept unsigned input for diagnostic semantic replay without touching consumer state, and report authenticity `NOT_PROVEN`/`UNAUTHENTICATED`, **never `SIGNED` or `ACCEPTED`**. No new inspection command is required. Legacy inspection is additionally constrained by B07.

**A07 — Trust material failure (K2).** With all three required flags supplied, malformed, absent or unreadable allowed-signers/signature files and inconsistent trust identity must fail closed with no state mutation. Unreadable/unavailable prerequisites emit `COULD_NOT_LOOK`/exit 2 and no uncaught traceback; a checkably invalid signer emits `REFUSED`/exit 1. The original missing-`--allowed-signers` path is explicitly pinned in A02. Never silently substitute a self-digest for failed signature checking.

**A08 — OPTIONAL, OWNER CHOICE K6: atomic state replacement.** If Chad chooses `A08_NOW`, an interrupted write **before atomic replacement** must leave the previous state file byte-for-byte intact (or preserve absence for first use); a successful acceptance must atomically publish complete, valid JSON with the expected consumed digest/anchor. Write the candidate to a temporary file **in the state file's directory**, flush/close it, then replace using `os.replace`; test an injected failure in temporary-file serialization and an injected failure immediately before replacement, followed by successful recovery/retry. Temporary files are cleaned or safely identified for cleanup. Do not claim guaranteed survival of power loss or disk/controller failure unless a separate durability protocol is measured. If Chad chooses `A08_BACKLOG`, this row is **NOT_IN_SCOPE_BY_OWNER** with a dated known-limitations entry; no test-pass or fix claim is made.

## B — W2: locally trusted contract binding and backwards-compatible inspection

**B01 — New format and explicit binding (K3/K5).** New packages use schema `sv.package/1` with exactly `contract: {"id": "sv.gate/0", "conformance_digest": "44823d0ff707213ae8bc310ed8b21e135f8e742fd8834e8f9474743d3a250628"}`; `sv.gate/0` already includes the contract version, so **no separate `contract.version` field** is added. Both fields participate in the canonical package-body digest and the detached signature over exact bytes. The verifier compares the package fields to its **locally pinned** `TRUSTED_CONTRACTS` map (`sv.gate/0` to the digest above), not a package-provided authority. The shipped vector conformance check must independently reproduce the locally pinned digest from the exact same frozen 4,690-vector corpus.

**B02 — Closed schema controls (K3).** For v1, missing/malformed `contract.id` or `contract.conformance_digest`; unknown keys (including a fictitious separate `contract.version`); duplicated JSON keys; non-finite numbers; and unsupported `schema` versions all fail closed. A correct new v1 package and its recognized fields pass the *same* closed-schema checks. Required contract values never silently default to trusted values.

**B03 — Contract substitution, decisive negative (K3/K5).** Begin with a valid signed v1 package. Substitute (a) a wrong digest with valid `sv.gate/0` ID, (b) an unrelated ID with the unchanged digest, (c) version-bearing ID `sv.gate/1` with the unchanged digest. Recompute the package self-digest and re-sign with an **authorized throwaway signing key** so package integrity and authenticity still pass. **Each must independently FAIL** the trusted contract binding check with a reason naming the mismatched field. An implementation comparing a package digest only to itself fails this test.

**B04 — Positive local comparison (K5).** A valid signed v1 package with exactly trusted `contract.id` and `contract.conformance_digest` must pass the contract check and the full verifier. `TRUSTED_CONTRACTS` must be a locally pinned constant verified against the independently executed Gate-vector conformance tool in CI. Demonstrate B03 refusing all substitutions and B04 accepting the correct pair; self-attestation never counts.

**B05 — Gate decision behavior unchanged.** Verify **both** kernel and independently coded replay against all **4,690 pinned contract vectors**, with identical decisions, reason ordering and the existing conformance digest; run the documented conformance and mutation checks. The v1 packaging change must not alter any `sv.gate/0` decisions, including the existing all-DEFAULTED `ALLOW` limitation. A change to Gate semantics requires an explicit, separate owner-approved revision: it is **not** a passing P-001 implementation.

**B06 — Preserve archival bytes (K4).** Before code changes, enumerate recursively and SHA-256 manifest **every** tracked `sv.package/0` JSON, its corresponding `.sig` if present, and witness log; repeat after implementation and require byte-identical hashes. Claude's source audit reported **17 old JSON packages and 8 signatures**; reconcile these counts with a pinned tree listing, and fail the manifest test if expected files vanish. Do not rewrite, reseal, resequence or re-sign originals. Signed legacy files still validate their original signature bytes in explicit legacy inspection and report `LEGACY_UNBOUND`; **unsigned** legacy files also remain inspectable, reporting `LEGACY_UNBOUND` and `UNAUTHENTICATED`/`NOT_PROVEN` rather than an invented signature.

**B07 — Explicit legacy separation (K4).** The hardened consumer refuses all `sv.package/0` production acceptance, even with historical valid signature and witness; state stays unchanged. Explicit legacy inspection of original signed **and unsigned** v0 files reports `LEGACY_UNBOUND`, independent signature status (`SIGNED` with a valid supplied signature or `NOT_PROVEN` without one), and their historical semantic results without retroactive contract binding. An inspection-only success is never acceptance. Signed, bound v1 still passes A01.

**B08 — Compatibility and documentation.** Published examples state the separate roles of new signed v1 production consumption, explicit unbound v0 inspection, the local Gate contract trust anchor, witness/replay freshness boundaries and signature limits. No unsupported promise that all old scripts accept v1 unchanged. New example commands must be tested end to end on the pinned CI platform using throwaway keys, with preserved command lines and outputs. If one environment lacks `ssh-keygen`, record `NOT_TESTED` for that environment; do not report a successful signature check there.
