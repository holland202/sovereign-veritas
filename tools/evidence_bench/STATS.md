# STATS — exact re-analysis of v0, A1 and A2 (the original 39 cases)

**Status: Draft, verified reference code.** Container only — NOT VALIDATED on the S25 Ultra.
Written 2026-10-02 after an outside review asked whether the published percentages could be
recomputed from the raw logs. They can — every table below is generated by `analyze.py` from
the raw result rows, and `verify_claims.py` fails if any table here drifts from that output.
No raw result was changed. What changed is how much the numbers are allowed to mean.

## What this re-analysis found wrong (read first)

1. **No direct-arm model reliably beats "always answer NOT_SUPPORTED".** On a paired exact
   McNemar test against the constant, Qwen3.5-2B direct is 9 cases better / 6 worse
   (p = 0.607) and Qwen3.5-4B direct 13 / 7 (p = 0.263). v0 P1 and A1-P1 were registered as
   point-estimate comparisons and stay *confirmed by their registered rule*, but on 39 cases
   that rule cannot separate 53.8% from 46.2%. Read those confirmations as "not ruled out",
   not as "better than abstaining".
2. **"Decomposition made the 4B model less safe" is withdrawn.** The registered A2-P2 is still
   refuted by its rule (unsafe accept 5/30 → 7/30), but the paired test is 5 cases one way and
   3 the other, p = 0.727. The honest statement is "decomposition did not make the 4B safer";
   the increase is indistinguishable from noise. This wording was also in a LinkedIn draft.
3. **A published control number depended on unrelated files.** `score.py` drew its
   "shuffled-gold p95" for every model from one shared random stream, so adding the 4B result
   file changed Qwen2.5-1.5B's p95 from the published 0.4359 to 0.4615 in the committed
   `score_report.json`. Both values reproduce exactly from the raw files (`legacy_mc.py`).
   The exact permutation 95th percentile is 18/39 = 0.4615. Every registered "beats the
   shuffle" verdict is unchanged under the exact test.
4. **The output parsers failed open.** `UNSUPPORTED` parsed as SUPPORTED and `UNTRUE` /
   `NOT TRUE` as TRUE. None of the 608 recorded outputs contained such a string, so no number
   changes; the hardened parser (`parsing.py`) agrees with the legacy one on all 608 and is
   used from H1 on.
5. **The registered consensus rule is not fail-closed.** `consensus.unanimous` can delete a
   refutation (v0 case C5-02: Qwen3.5-2B saw the conflict, the consensus with LFM2.5 said
   SUPPORTED). Exhaustively, 140 of 819 two-extractor assignments on 1–3 items accept where a
   member alone would not. `consensus_veto.py` fixes this with a proof (0 / 819).
6. **The speed columns in RESULTS.md are not throughput measurements.** Each call generated
   3–6 tokens, so "gen tok/s" is dominated by per-call overhead. "Prompt tok/s" counts only
   the uncached part of the prompt: the Qwen models reuse llama-server's cached system prompt
   (81–94 tokens processed per call) while LFM2.5 reprocesses all ~336, so the column compares
   different workloads. A1-P7's "≥ 5 gen tok/s" was therefore badly operationalised; the
   replacement instrument is `device_bench.py` (fixed pp512/tg128 workload, registered as
   H1-P10).
7. **The gate itself fails open on unreadable answers.** Found by the new property tests
   (`tests/test_gate_properties.py`), the first time anyone checked that an unreadable extractor
   answer can never create an acceptance. `gate.py` reads INVALID as NEITHER, and its docstring
   says this "fails toward NOT_SUPPORTED, never toward acceptance". That holds for one item and
   fails for a case: if the unreadable answer belongs to the item that refutes the claim, the
   veto disappears (answers [TRUE, INVALID] on two admissible items → SUPPORTED). Over every
   pattern of readable answers on 1–3 admissible items with one answer replaced by INVALID,
   11 of 102 corruptions turn a non-acceptance into an acceptance, and 11 turn a non-refutation
   into a refutation. No recorded answer was unreadable (0 of 296 v0/A1/A2 item answers), so no
   published number changes. `gate.py` is bound by hash in `PREREG_H1.md` and stays as
   registered. `gate_strict.py` is the proposed fix, not preregistered: an unreadable answer on
   an admissible item makes the verdict NOT_SUPPORTED (0 of 102). Same root cause as item 5:
   *unknown* was treated as *no opinion*.

## What survives

- Decomposition (model labels items, `gate.py` decides) reduced wrong acceptances for three
  of four models with paired significance after Holm correction across the four models:
  Qwen3.5-2B 7 → 0 discordant (p = 0.016, Holm 0.047), LFM2.5-1.2B 17 → 0 (p < 0.001),
  Qwen2.5-1.5B 9 → 1 (p = 0.021, Holm 0.047).
- Qwen3.5-2B decomposed is the first configuration that beats always-NOT_SUPPORTED on a
  paired test (18 better / 7 worse, p = 0.043, not multiplicity-adjusted).
- All of it is in-sample: A1 and A2 were designed after seeing v0 on these same 39 cases.
  H1 (`PREREG_H1.md`) is the out-of-sample test.

## Testing the instruments

`python -m unittest discover -s tests -v` runs the suite. It uses only the standard library;
the scipy cross-checks skip themselves where scipy is absent (Termux). It covers the parsers
against every recorded output; seeded property and metamorphic tests of the gate and both
consensus rules (order never matters, inadmissible items never matter, framing never matters,
the freshness boundary is inclusive); exhaustive checks of the consensus theorem and of the
corruption counts in item 7; the oracle against all 149 case labels; the label audit's power
(each of the 264 single-label corruptions of the held-out set is caught); byte-for-byte
regeneration of the held-out file from its seed; the hashes the preregistrations bind; this
document's numbers (`verify_claims.py`, with negative controls that change one number and must
fail); and `device_bench.py` end to end against a fake `llama-bench`.

`python mutate.py` asks whether those tests have teeth. It plants one deliberate bug at a time
in the gate, the strict gate, the veto rule, the parsers and the statistics, and reruns the
behavioural tests on a scratch copy: 17 mutants, 17 killed, 0 survived
(`results/mutation_report.json`). Hash checks are left out of that run, because a changed
`gate.py` fails its hash whatever the change does.

## Method
Exact Clopper-Pearson intervals, exact McNemar, exact permutation distribution (contingency
enumeration, integer arithmetic), Holm step-down — all in `stats.py`, stdlib only, and
cross-checked against scipy (`tests/test_stats.py`). The v0 "unsafe accept" denominator is
the 30 gold-negative cases; REFUTED recall is over the 12 gold-REFUTED cases.
